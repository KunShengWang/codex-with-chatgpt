# 常用功能异常修复与验证（2026-09-05）

本轮修改 C2C 本地 CLI、地址状态和配套技能，不操作 enterprise-agent 的
连接器、任务检查点或项目代码。保留此前浏览器诊断和手动配置改动。

## 已修复

1. 新地址被 doctor 保存后，下一次检查错误地认为无需重连。
   现在区分观测地址与已确认配置地址。连续 doctor/start 记录不会清除
   待配置状态；新连接也保持待配置，直到实际完成后记录确认。
2. 增加 `connector-confirm --url`，仅在用户报告完成配置（或自动模式观察到
   授权完成）后调用。旧地址确认被拒绝；该命令不代表文件读取成功。
3. `doctor --no-fix` 原来也写入地址并生成配对码。现在这些动作仅在修复
   模式执行。回归测试比对地址文件原始内容及配对会话状态。
4. 重复修复检查不再更换仍有效的配对码。已用或过期后才需要新码；
   显式 `pair` 仍可主动换码。配对码不新增持久化存储。
5. 手动模式的 CLI 不再承诺自动删除、重装。doctor 输出包含手动模式、
   认证方式、描述、页面链接、地址和配对状态，便于一次性交接信息。

## 验证

- TypeScript 类型检查、构建通过；构建后的 CLI 可识别新命令。
- 新增 4 项地址状态测试、2 项实际 CLI/本地 HTTP 集成测试。
- 集成测试使用隔离 C2C 状态目录、隔离 Codex 配置、临时工作区和回环地址。
  不访问真实公网连接器，不启动 Cloudflare，不写真实任务检查点。
- CLI 流程覆盖：地址变化 → 首次 doctor → 重复 doctor → 原码仍可用 →
  配对后仍待配置确认 → 拒绝旧地址确认 → 确认当前地址 → doctor 不再待配置。
- 首次并行全量运行：151 成功、1 失败；失败为既有 MCP 重命名过滤测试的
  `fetch failed / ECONNRESET`，没有断言证明数据泄漏。单独运行该文件 16 项通过。
- 完整串行复测：`vitest run --maxWorkers=1 --minWorkers=1`，15 文件、152 项通过。
  未修改测试断言来掩盖首次失败，也未将未知原因的连接重置宣称为已修复。
- 配对有效期、单次使用、次数限制、OAuth、文件读取、搜索、Git 过滤、
  会话检查点等既有测试包含在上述全量测试中。

## 生效范围与限制

构建产物已更新，技能已同步到本地安装目录。没有修改常驻服务代码，因此
无需为本轮修复重启已有连接。上述测试结果记录于本地提交前。

旧版状态文件以旧记录的地址作为兼容基线。如果旧版早已覆盖未确认地址，
历史信息无法自动恢复，仍需通过实际 ChatGPT 读取判断并手动修复。

本轮没有替用户进行真实授权或重建连接器，也没有再次重放浏览器发送。
升级后浏览器的路由错误及约 35–42 秒读取延迟仍未根治，见
[浏览器诊断报告](c2c-browser-diagnostic-2026-09-05.md)。
